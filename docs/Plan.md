# DocMan 서비스 플랜

> 작성일: 2026-09-26 · 근거 문서: `docs/DocMan-draft.md`
> 이 문서는 [개발 절차 1. 플랜 단계]의 결과물이며, 다음 단계인 PRD(`docs/PRD.md`)의 기준이 된다.

---

## 1. 서비스 목표

문서(.pdf, .docx, .md, .txt)나 사진을 올리면 AI가 내용을 분석하고 요약한다. 원본과 분석 결과는 사용자 본인의 Google Drive `DocMan` 폴더에 쌓이고, 대시보드에서 목록·검색·주제 그래프로 다시 찾아볼 수 있다.

- 사용자: 개발 의뢰자 1인
- 비용: 무료 (무료 호스팅과 무료 API 사용량 안에서 운영)
- 사용 환경: Windows PC 브라우저, 안드로이드 스마트폰(PWA로 설치)

---

## 2. 초안 검토 결과 및 결정 사항

### 2.1 의뢰자와 확정한 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 안드로이드 앱 형태 | **PWA** (Progressive Web App) | 웹 코드 하나로 PC와 폰을 모두 지원한다. 폰에서 '홈 화면에 추가'로 설치하고, 카메라 촬영은 `<input type="file" accept="image/*" capture>`로 한다. 스토어 등록이 필요 없다. |
| AI 분석 엔진 | **Google Gemini API** | 무료 사용량이 있고, PDF와 이미지를 직접 읽어서 사진 글자 추출(OCR)을 따로 붙이지 않아도 된다. |
| 분석 MD 저장 구조 | **자료별 MD 파일 + 카테고리별 누적 표 MD 파일 둘 다 생성** | 초안에 두 해석이 모두 있었다(자료별 MD, 최신 항목이 맨 위인 표). 둘 다 만들고, 대시보드용 카운트와 목록은 `index.json`에 따로 둔다. |
| HWP 지원 | **MVP에서 제외** | 브라우저에서 HWP를 안정적으로 읽기 어렵다. MVP에서는 PDF로 바꿔 올리도록 안내하고, 이후 확장 항목으로 남긴다. |

### 2.2 AI 제안 기본값 (의뢰자가 바꿀 수 있음)

| 항목 | 제안 |
|---|---|
| 프레임워크 | React + Vite + TypeScript. Roadmap의 Phase(라우트, 컴포넌트, 커스텀 훅, 타입 정의)와 잘 맞는다. |
| 서버 | 없음. 정적 SPA를 GitHub Pages에 배포하고, 브라우저에서 Google Drive API와 Gemini API를 직접 호출한다. |
| Google 인증 | Google Identity Services 토큰 방식. 권한 범위는 `drive.file`(DocMan이 만든 파일만 접근)로 해서 구글 앱 검수가 필요 없게 한다. 본인 계정을 테스트 사용자로 등록한다. |
| Gemini API 키 | 코드와 GitHub에 넣지 않는다. 앱 설정 화면에서 입력해 브라우저 localStorage에만 저장한다. |
| 그래프 분석 | 노드 = 주제, 연결선 = 두 주제가 공유하는 키워드 수. 가벼운 그래프 라이브러리 1개(예: vis-network)만 쓴다. |
| 원문 보기 | Drive 파일의 `webViewLink`를 새 탭으로 연다. |

### 2.3 초안 해석 메모

- "총 주제 및 건수": 카테고리별 **서로 다른 주제의 수**와 **등록 건수**로 해석한다.
- "매번 다시 집계하지 않고": 등록할 때마다 `index.json`의 카운트를 1씩 올려 저장한다.
- 초안의 오타(여북 → 여부, 버큰 → 버튼, 프로잭트 → 프로젝트)는 뜻대로 해석했다.

## 3. 지원 입력

| 형식 | 처리 방법 |
|---|---|
| PDF | 파일을 Gemini에 그대로 전달 |
| DOCX | mammoth.js로 텍스트를 뽑아 Gemini에 전달 |
| MD, TXT | 텍스트를 그대로 읽어 Gemini에 전달 |
| 사진 (JPG, PNG, HEIC 등) | 이미지를 Gemini에 전달해서 글자 추출과 분석을 한 번에 처리 (HEIC는 JPEG로 변환) |
| HWP | MVP 미지원. "PDF로 변환해서 올려주세요" 안내 |

업로드 방식: 드래그 앤 드롭, 파일 선택, 스마트폰 카메라 촬영.

## 4. 기능 목록

### 4.1 초기화
- 로그인 후 Drive에 `DocMan/` 폴더가 있는지 확인하고, 없으면 만든다.
- `Documents/`, `Photos/` 하위 폴더와 빈 누적 표(`Documents.md`, `Photos.md`), `index.json`이 없으면 만든다.

### 4.2 자료 입력
- PC와 폰: 미리 가지고 있는 파일을 업로드 (드래그 앤 드롭, 파일 선택)
- 폰: 카메라 버튼을 눌러 촬영 후 업로드
- 파일 형식으로 카테고리(일반 문서 / 사진)를 자동으로 정한다.

### 4.3 분석
- 일반 문서: 제목, 주제, 키워드(5개 이하), 핵심 내용(10줄 이하, 개조식)
- 사진: 텍스트 추출 후 제목, 주제, 키워드(3개 이하), 핵심 내용(4줄 이하)
- Gemini의 JSON 출력 모드를 써서 결과 형식을 고정한다.
- 저장 전에 분석 결과를 화면에 보여준다.

### 4.4 저장 (순서대로)
1. 원본 파일을 카테고리별 `originals/` 폴더에 저장
2. 자료별 분석 MD 파일을 `summaries/` 폴더에 저장
3. 카테고리 누적 표 MD(`Documents.md` 또는 `Photos.md`)의 **맨 위**에 새 행 추가
4. `index.json`의 건수·주제 수를 올리고 항목 메타데이터를 추가

MD 필드: 제목, 주제, 키워드, 핵심 내용, 생성 일자, 원본 링크.
누적 표에서 핵심 내용 셀 안의 줄바꿈은 `<br>`로 표시한다.

### 4.5 대시보드
- **1단계 박스**: [일반 문서], [사진] 카테고리별 주제 수와 건수 (`index.json`에서 바로 읽음)
- **2단계 박스**: 카테고리별 최근 자료를 한 줄에 '제목 · 주제 · 키워드'로 표시. 처음에 10개를 보여주고, 스크롤하면 이전 자료가 이어서 나온다.
- **요약 박스**: 목록에서 항목을 누르면 팝업으로 '핵심 내용'을 보여준다. [닫기]와 [원문 보기] 버튼이 있다.

### 4.6 검색
- 주제나 키워드를 입력하면 결과를 [일반 문서]와 [사진]으로 나눠 별도 박스에 10개씩 표시한다.
- 스크롤과 [닫기] 버튼이 있다.
- 항목을 누르면 요약 박스가 열린다.

### 4.7 그래프 분석
- [그래프 분석] 버튼을 누르면 등록된 주제들의 연관 관계를 그래프로 보여준다.
- 그래프에서 주제를 누르면 그 주제로 검색이 실행된다.

### 4.8 원문 보기
- 대시보드, 검색, 그래프에서 열린 요약 박스 모두 [원문 보기] 버튼을 가진다.
- 누르면 Drive의 원본 파일이 새 탭으로 열린다.

### 4.9 확장성
- 파일 형식별 텍스트 추출기(extractor)와 카테고리별 분석 프롬프트를 모듈로 나눈다. 새 형식(예: HWP)이나 새 카테고리는 모듈을 추가해서 붙인다.
- Drive 접근과 Gemini 호출은 서비스 계층에 모아서, 화면 코드가 API를 직접 부르지 않게 한다.
- 화면 기능은 `features/` 아래에 기능 단위로 나눠서, 새 기능을 폴더 하나로 추가할 수 있게 한다.

## 5. Google Drive 저장 구조

```
DocMan/
├─ index.json              # 카운트, 주제 목록, 항목 메타데이터 (대시보드·검색·그래프용)
├─ Documents/
│  ├─ originals/           # 원본 문서
│  ├─ summaries/           # 자료별 분석 MD
│  └─ Documents.md         # 누적 표 (최신 항목이 맨 위)
└─ Photos/
   ├─ originals/           # 원본 사진
   ├─ summaries/           # 자료별 분석 MD
   └─ Photos.md            # 누적 표 (최신 항목이 맨 위)
```

`index.json` 예시 구조:

```json
{
  "version": 1,
  "counts": { "document": 0, "photo": 0 },
  "topics": { "document": {}, "photo": {} },
  "items": [
    {
      "id": "…",
      "category": "document",
      "title": "…",
      "topic": "…",
      "keywords": ["…"],
      "summary": ["…"],
      "createdAt": "2026-09-26T10:00:00+09:00",
      "originalFileId": "…",
      "originalLink": "…",
      "summaryFileId": "…"
    }
  ]
}
```

- `topics`는 주제별 건수를 담는다. 키 개수가 곧 '주제 수'다.
- `items`는 최신 항목이 앞에 온다.

## 6. 시스템 구성

```
[브라우저 / PWA]
   ├── Google Identity Services ── 로그인, 액세스 토큰
   ├── Google Drive API ────────── 폴더·파일·index.json 읽기/쓰기 (DB 역할)
   └── Gemini API ──────────────── 문서·사진 분석
```

서버와 별도 DB는 없다. Google Drive가 저장소 역할을 한다.

소스 폴더 구조(안):

```
src/
├─ types/                 # 공통 타입 (Item, Category, AnalysisResult 등)
├─ services/
│  ├─ auth/               # Google 로그인, 토큰 관리
│  ├─ drive/              # Drive 폴더·파일·index.json 처리
│  └─ gemini/             # 분석 요청, 프롬프트, 결과 검증
├─ extractors/            # 파일 형식별 추출기 (pdf, docx, text, image)
├─ features/
│  ├─ upload/             # 업로드·카메라·분석·저장 흐름
│  ├─ dashboard/          # 1·2단계 박스
│  ├─ search/             # 검색
│  └─ graph/              # 그래프 분석
├─ components/            # 공통 UI (요약 박스 팝업, 목록, 버튼 등)
└─ hooks/                 # 공통 커스텀 훅
```

## 7. 개발 원칙

- 꼭 필요한 도구만 쓴다: React, Vite, TypeScript, vite-plugin-pwa, mammoth, 그래프 라이브러리 1개. 이 밖의 라이브러리는 필요성을 설명하고 의뢰자와 상의한 뒤 추가한다.
- 무료 배포: 코드는 의뢰자 GitHub 저장소에 올리고, GitHub Actions로 GitHub Pages에 배포한다.
- 보안: API 키, OAuth 비밀값, 개인정보는 저장소에 올리지 않는다. OAuth 클라이언트 ID는 공개돼도 되는 값이라 빌드 환경 변수로 넣는다.
- 1인 사용 기준으로 단순하게 만든다. 여러 사용자, 권한 관리, 서버 기능은 넣지 않는다.
- 커밋 메시지는 Conventional Commits 형식, 한글, 제목 50자 이내.

## 8. 알려진 제약

- Gemini 무료 사용량에는 분당·일일 요청 한도와 파일 크기 제한이 있다. 한도를 넘으면 안내 메시지를 보여준다.
- 구글 로그인 토큰은 약 1시간마다 만료된다. 만료되면 다시 로그인을 요청한다.
- `drive.file` 범위라서, DocMan 밖에서 Drive에 직접 넣은 파일은 앱에서 보이지 않는다.
- 두 기기에서 동시에 저장하면 `index.json`이 덮어써질 수 있다. 1인 사용이라 MVP에서는 이 위험을 받아들인다.
- HWP는 MVP에서 지원하지 않는다.
