# DocMan ROADMAP

> 근거 문서: `docs/PRD.md` (확정) · 상태: 확정 (2026-09-26)
> 원칙: **구조 우선 접근법(Structure-First)** — 골격 → 공통 요소 → 더미 UI → 실제 연동 → 배포 순서를 지키고, 앞 Phase가 끝나기 전에 다음 Phase 작업을 섞지 않는다.

## Phase 구성

| Phase | 목표 | 외부 API 사용 |
|---|---|---|
| 1 | 전체 골격 구축 (프로젝트, 라우트, 빈 페이지, 타입) | 없음 |
| 2 | 공통 요소 구현 (공통 컴포넌트, 훅, 유틸, 서비스 인터페이스) | 없음 |
| 3 | UI 완성 (더미 데이터로 모든 화면과 흐름 동작) | 없음 |
| 4 | 핵심 기능 구현 (Google 로그인, Drive, Gemini 연동) | 있음 |
| 5 | 최적화 및 최종 배포 (PWA, GitHub Pages) | 있음 |

**서비스 특성에 맞춘 조정**
- 서버가 없고 외부 API가 Google과 Gemini 두 개뿐이라 기본 5 Phase를 그대로 쓴다.
- Phase 2에서 서비스 계층을 **인터페이스 + 더미 구현**으로 만들고, Phase 4에서 실제 구현으로 바꿔 끼운다. 화면 코드는 Phase 3 이후 거의 고치지 않게 하려는 것이다.
- Phase 4는 연동 위험이 크므로 작은 단계(4-1 ~ 4-6)로 나누고, 단계마다 실제 계정으로 확인한다.
- Phase 4를 시작하려면 `docs/Prepare.md`의 준비 사항(OAuth 클라이언트 ID, Gemini API 키)이 끝나 있어야 한다.

## Phase 1: 전체 골격 구축

**목표**: 모든 페이지로 이동할 수 있는 빈 앱

| 작업 | 관련 기능 |
|---|---|
| Vite + React + TypeScript 프로젝트 생성, 폴더 구조 생성 (`types`, `services`, `extractors`, `features`, `components`, `hooks`) | - |
| 라우트 구성: `/login`(P01), `/`(P02), `/upload`(P03), `/graph`(P04), `/settings`(P05) | 전체 |
| 빈 페이지 컴포넌트 5개와 공통 레이아웃(상단 메뉴: 대시보드·업로드·그래프·설정) | 전체 |
| 로그인 여부로 페이지 접근을 막는 가드 (이 단계에서는 임시 플래그 사용) | F001 |
| 타입 정의: `Category`, `Item`, `AnalysisResult`, `IndexData`, `AppSettings` | F007~F011 |
| 서비스 인터페이스 정의: `AuthService`, `DriveService`, `AnalysisService`, `Extractor` | F001, F004, F007~F009 |

**완료 기준**: `npm run dev`로 실행해 모든 경로가 열리고, `npm run build`와 타입 검사가 오류 없이 통과한다.

## Phase 2: 공통 요소 구현

**목표**: 화면과 기능이 공통으로 쓰는 부품 완성

| 작업 | 관련 기능 |
|---|---|
| 공통 컴포넌트: `Modal`(닫기 버튼 포함), `Button`, `ItemRow`(제목·주제·키워드 한 줄), `ScrollList`(10개씩 더 불러오기), `Spinner`, `ErrorMessage`, `EmptyState` | F011, F012, F014 |
| 커스텀 훅: `useAuth`, `useSettings`(API 키 localStorage 저장·삭제), `useIndex`(index.json 불러오기·캐시), `usePagedList` | F001, F003, F010, F011 |
| 유틸: 확장자로 카테고리 판별·지원 형식 확인, 날짜 형식, MD 생성(자료별 MD, 누적 표 행, `<br>` 처리), 검색(주제·키워드 부분 일치), 그래프 데이터 생성(주제 노드, 공유 키워드 연결선) | F005, F009, F014, F015 |
| 추출기: text(md/txt), docx(mammoth), pdf·image(Gemini에 파일 그대로 전달하도록 준비) | F005, F007, F008 |
| 더미 서비스 구현: `MockAuthService`, `MockDriveService`, `MockAnalysisService` + 더미 데이터(문서·사진 각 25건 이상) | 전체 |
| 유틸 단위 테스트 (Vitest): 카테고리 판별, MD 생성, 검색, 그래프 데이터, index.json 갱신 로직 | F005, F009, F014, F015 |

**완료 기준**: 유틸 단위 테스트가 통과한다. 공통 컴포넌트를 빈 페이지에 넣어 보았을 때 모양과 동작이 정상이다.

## Phase 3: UI 완성 (더미 데이터)

**목표**: 더미 서비스로 PRD의 모든 화면과 흐름이 동작

| 작업 | 관련 기능 |
|---|---|
| P01 로그인: [Google로 로그인] 버튼 → 초기화 진행 표시 → P02 이동 | F001, F004 |
| P02 대시보드: 검색창, 1단계 박스(주제 수·건수), 2단계 박스(최근 목록, 10개씩 스크롤), 빈 상태 | F010, F011, F014 |
| M01 요약 박스: 제목·카테고리·생성 일자·핵심 내용, [원문 보기], [닫기] | F012, F013 |
| M02 검색 결과 박스: 문서/사진 구분, 10개씩 스크롤, [닫기], 결과 없음 | F014 |
| P03 업로드: 드롭 영역, [파일 선택], [카메라](폰만), 분석 결과 표시, [저장]/[취소], 예외 메시지 3종 | F005~F009 |
| P04 그래프: 그래프 라이브러리 적용, 노드 클릭 → M02 | F015, F014 |
| P05 설정: API 키 입력(가림)·저장·삭제, 계정 표시, [로그아웃] | F002, F003 |
| 반응형: PC 화면과 폰 화면(가로 375px) 모두 깨지지 않게 | 전체 |

**완료 기준**: PRD의 페이지별 상세에 적힌 동작과 예외를 더미 데이터로 하나씩 눌러서 확인한다. 브라우저 모바일 보기에서도 같은 확인을 한다.

## Phase 4: 핵심 기능 구현 (API 연동)

**목표**: 더미 서비스를 실제 서비스로 바꿔 실제 계정에서 동작
**시작 조건**: `docs/Prepare.md` 준비 완료

| 단계 | 작업 | 관련 기능 | 확인 방법 |
|---|---|---|---|
| 4-1 | Google Identity Services 로그인·로그아웃, 토큰 만료 시 재로그인 | F001, F002 | 실제 계정으로 로그인·로그아웃 |
| 4-2 | Drive 초기화: 폴더·빈 누적 표 MD·index.json을 없을 때만 생성 | F004 | 처음 실행하면 생성되고, 두 번째 실행하면 중복이 생기지 않음 |
| 4-3 | Gemini 분석: 문서·사진 프롬프트, JSON 출력 형식 고정, 키워드·줄 수 제한 검증 | F007, F008 | PDF·DOCX·MD·TXT·사진 각 1개 분석 |
| 4-4 | 자료 저장: 원본 → 자료별 MD → 누적 표 맨 위 행 추가 → index.json 갱신 | F009 | Drive에서 파일 4종과 카운트 증가 확인 |
| 4-5 | 대시보드·검색·그래프를 실제 index.json으로 표시, 원문 보기 링크 | F010~F015 | 4-4에서 저장한 자료가 모든 화면에 나타남 |
| 4-6 | 폰 카메라 촬영 업로드 (HEIC → JPEG 변환 포함) | F006 | 안드로이드 폰에서 촬영·저장 |
| 공통 | 오류 처리: 토큰 만료, API 키 없음·잘못됨, Gemini 한도 초과, 저장 중 실패 | 전체 | 각 상황을 일부러 만들어 메시지 확인 |

**완료 기준**: 실제 계정으로 "업로드 → 분석 → 저장 → 대시보드 확인 → 검색 → 그래프 → 원문 보기"를 PC와 폰에서 끝까지 해 본다.

**목표**: 폰에 설치할 수 있는 앱으로 무료 배포

|---|---|

**완료 기준**: 배포 주소에서 PC와 폰 모두 Phase 4 완료 기준 시나리오가 통과하고, 폰 홈 화면에 앱으로 설치된다.
