# [목적] 
문서(.pdf, .docx, .md, .txt, .hwp)나 사진을 업로드하면 그 자료의 내용을 분석하고 요약하여 보여 주고 구글 드라이브에 저장하는 웹페이지. 

---

# [형태] 
윈도우즈 PC 용 웹페이지와 안드로이드 스마트폰 앱 두가지 형태로 제작함.

---

# [웹페이지 이름] 
DocMan

# [기능]
## 1. 초기화 기능
- 구글 드라이브에 DocMan 폴더 존재 여부 확인: 없으면 생성
- 일반 문서와 사진 카테고리 별로 표 존재 여북 확인: 없으면 더미 표를 생성

## 2. 문서 자료와 사진 입력 기능
### 1) PC와 스마트폰: 사용자가 사전에 확보한 문서 자료나 사진을 업로드
### 2) 스마트폰: 앱에 표시된 카메라 버튼을 클릭한 후 카메라로 찍어서 업로드
### 3) 업로드 방식
- Drag and Drop 기능 
- 파일 업로드 기능
- 스마트폰 카메라 촬영 기능

## 3. 자료 분석 및 저장 기능

### 1) 분석 기능
- 일반 문서: 제목, 주제, 키워드 (5개 이내), 핵심 내용(최대 10줄 이내에서 개조식으로 요약)
- 사진: 텍스트를 추출하여 제목, 주제, 키워드 (3개 이내), 핵심 내용(최대 4줄 이내로 요약)  

### 2) 저장 기능
- 원본 자료: 문서와 사진을 별도 카테고리로 저장
- 일반 문서와 사진에 대한 분석 내용을 별도의 MD 파일로 저장
- 분석 내용 MD 파일을 구성하는 필드: 제목, 주제, 키워드, 핵심 내용, 생성 일자, 원 자료 (문서, 사진) 링크
- MD 파일 구성: 각 필드를 표의 형태로 정리. 가장 최근에 추가된 내용을 표의 가장 상단부에 추가    
- 저장 장소: 사용자 구글 드라이브 [DocMan] 폴더 

## 4. 분석 자료 확인 기능
### 1) 형태: 대시 보드 형태로 체계(단계)적으로 표시

### 2) 대시 보드 항목
#### 1단계 탭(박스)
- [일반 문서], [사진] 두 카테고리 별로 총 주제 및 건수 표시. 
- 매번 다시 집계하지 않고 자료를 등록할 때 마다 카운트 수를 증가하고 기억하는 방식 사용할 것

#### 2단계 탭(박스)
- 카테고리 별로 가장 최근에 등록된 자료에 대한 '제목', '주제', '키워드' 를 한 줄에 표시할 것. 
- 10개 자료를 10줄에 표시하며, 스크롤 다운하며 이전 자료들을 확인할 수 있도록 할 것.
- 2단계에서 나타나는 자료 리스트에서 특정 자료를 클릭하면 이 자료에 대한 MD 파일 내용 중 '핵심 내용' 필드를 별도의 [요약 박스](필요하면 팝업 박스 형태)에 보여줌, 
- [요약 박스]는 닫기 버튼을 클릭하면 사라져야 함. 
### 3) 검색 기능 
- 주제나 키워드를 입력하면 관련된 항목들을 [일반 문서]와 [사진] 으로 구분하여 한 번에 10개씩 별도 박스에 표시함. 
- 스크롤 기능과 닫기 버큰이 있어야 함. 
- 특정 항목을 클릭하면 [요약 박스]가 나타나고 닫기 버튼이 있어야 함.
### 4) 그래프 분석 기능
-  [그래프 분석] 버튼 또는 박스를 클릭하면, 등록 자료들의 '주제' 의 연관성을 그래프 뷰로 보여 준다. 
- 이 그래프에서 특정 주제를 클릭하면 '검색 기능'이 동작한다.
### 5) 원문 보기
- 2), 3), 4)에서 나타나는 [요약 박스]에는 '닫기 버튼' 외에 '원문 보기' 버튼이 있어야 한다.
- '원문 보기' 버튼을 클릭하면 원문이 나타나야 한다.   

## 5. 추가 기능
- 나중에 추가할 기능이 있을 경우 쉽게 추가할 수 있도록 고려하여 프로그램 아키텍쳐(스트럭쳐)를 만든다.

# [개발 절차] 

## 1. 플랜 단계
- 이 문서 (".\docs\DocMan-draft.md")를 AI가 검토하여 수정이나 제안할 사항이 있는 경우 개발 의뢰자와 상의하여 결정한다.
- 이후 전체 서비스의 목표, 기능, 구성, 개발 원칙 등을 정리한다.
- 그 결과를 .\docs\Plan.md 파일에 저장한다.

## 2. PRD 생성
- 플랜 결과를 바탕으로 아래 참고 사항을 준수하여 PRD를 생성한다. 
- 이후 개발 의뢰자와의 검토 및 상의를 통하여 PRD.md를 확정한다.
- 결과물은 .\docs/PRD.md 파일에 마크다운 형식으로 저장할 것.

```
[PRD 작성시 참고 사항]
- 성능 지표, 인프라 상세, 마일스톤, 페르소나 정보는 제외하여 최대한 토큰을 절약할 것
- MVP 버전에 필요한 필수 기능만 포함할 것
- 각 기능에는 식별을 위한 기능 ID(예: F001, F002...)를 부여할 것
- '기능 명세', '메뉴 구조', '페이지별 상세' 세 항목 간의 정합성을 완벽히 유지할 것
```

## 3. Roadmap 생성
- PRD를 기반으로 아래 참고사항을 반영하여 이 서비스 개발에 적합한 Roadmap을 생성한다. 
- 이후 개발 의뢰자와의 검토 및 상의를 통하여 Roadmap.md를 확정한다.
- 결과물은 .\docs/ROADMAP.md 파일에 마크다운 형식으로 저장할 것.

```
[Roadmap 작성시 참고 사항]
- '구조 우선 접근법(Structure-First)'을 엄격하게 적용할 것
- 개발 단계를 아래 5개의 Phase로 구성하는 것을 원칙으로 하되, 이 서비스의 특성을 고려하여 Phase를 제안하여 확정할 것. 
Phase 1: 전체 골격 구축 (라우트, 빈 페이지, 타입 정의)
Phase 2: 공통 요소 구현 (공통 컴포넌트, 커스텀 훅, 유틸리티)
Phase 3: UI 완성 (더미 데이터를 활용한 화면 구성)
Phase 4: 핵심 기능 구현 (API 및 DB 연동)
Phase 5: 최적화 및 최종 배포
```

## 4. 준비 사항
- Roadmap과 별도로 개발 의뢰자가 준비하여야 할 사항을 .\docs\Prepare.md 파일로 저장하여 안내한다.
